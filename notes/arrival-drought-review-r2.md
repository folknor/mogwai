# R2 - codex gpt-5.6-sol xhigh review of notes/arrival-drought-elimination-spec.md

The spec is not implementation-ready. I found five blocking issues and three smaller specification gaps.

1. [P1] The default production tape is not actually gated. The proposed realism gate uses seed 42, while the server derives a distinct FNV seed for each symbol in [source.rs](/home/folk/Programs/mogwai/crates/mogwai-server/src/source.rs:78). Seeds 7 and 1337 are only advisory in [the spec](/home/folk/Programs/mogwai/notes/arrival-drought-elimination-spec.md:200). Because the Weibull innovation remains unbounded, the relaxation is not a hard maximum-gap bound. Seed 42 can pass while the actual BTCUSDT tape still deserts. The asserted gate must include production symbol seeds over a pinned horizon, or the completion claim must be narrowed.

2. [P1] The new recurrence does not preserve `mean_duration_s`. In [D2](/home/folk/Programs/mogwai/notes/arrival-drought-elimination-spec.md:138), `w` depends on the previous duration and is therefore correlated with the expression it scales. Consequently, the expectation is not generally `mean_s`. This invalidates the claims that cadence and tick-count budgets remain unchanged, yet [Measured](/home/folk/Programs/mogwai/notes/arrival-drought-elimination-spec.md:285) gains no mean-gap statistic. The spec needs either a mean-preserving calibration of the intercept or an asserted realized-mean gate, followed by re-running the server seek-budget measurement.

3. [P1] The permitted Weibull retune omits a required coupled artifact. D5 allows changing `ACD_WEIBULL_SHAPE` toward 0.55, but innovations are normalized by the shape-0.60-specific `WEIBULL_MEAN_SHAPE_060` in [numeric.rs](/home/folk/Programs/mogwai/crates/mogwai-data/src/generated/numeric.rs:72). The artifact list mentions neither `numeric.rs` nor `weibull_mean_matches_known_constant`. Changing the shape without changing its mean normalization breaks the unit-mean innovation invariant. The spec must either freeze the shape at 0.60 or explicitly update the derived mean constant, imports, comments, and test.

4. [P1] The retune procedure cannot produce a unique artifact. Instructions such as "move by factors of 2", "raise toward 0.995", and "a day of iteration" in [D5 and D6](/home/folk/Programs/mogwai/notes/arrival-drought-elimination-spec.md:193) leave many valid constant sets and no deterministic selection rule. That conflicts with the project requirement that two implementers produce the same artifact. L1 should be followed by exact selected constants, or the spec must define a finite search grid, objective function, constraints, seed set, and tie-breaker.

5. [P1] One required gate silently runs zero relevant tests. The command `brokkr test -p mogwai-data session_curves` in [L2](/home/folk/Programs/mogwai/notes/arrival-drought-elimination-spec.md:353) does not match any test name. The ignored test is [session_modulation_reproduces_curves](/home/folk/Programs/mogwai/crates/mogwai-data/src/generated/tests.rs:970), and `brokkr check` does not run it. The command must use that exact name.

6. [P2] `empty_hour_frac` is not precisely or safely defined. The proposed `ts // 3600` bucket set includes partial boundary hours, while `(last_ts - first_ts) // 3600` counts elapsed whole hours differently. Short spans can produce a zero denominator, and boundary buckets can make the numerator inconsistent. The Rust instruction merely says "hour-bucket scan", so the corpus and generator can measure different quantities. The spec needs exact UTC bucket inclusion rules, boundary behavior, zero-span behavior, and matching Python/Rust fixtures. The percentile extraction from the coarse histogram similarly needs an exact bin-edge/interpolation rule.

7. [P2] The new drought test does not pin the claimed clustered shape. Mean duration plus `max_gap >= 5x mean` in [section 4.6](/home/folk/Programs/mogwai/notes/arrival-drought-elimination-spec.md:296) can pass for an independent heavy-tailed process with no clustered drought. Its upper-bound expression also refers to an undefined "thin-scaled slack". Pin the shape using duration ACF, longest consecutive sparse-hour run, or another explicit clustering statistic.

8. [P3] The survey overstates the re-bless set. The checkpoint tests compute a fresh reference stream from the changed generator and compare resumed output against it; they contain no old pinned tails to re-bless. Only `clean_regime_is_byte_identical` has literal stream bytes. Also, `build_fingerprint.py` always regenerates tracked `analysis/findings.md`, but the spec does not require its human-readable summary to gain the new dwell results.
